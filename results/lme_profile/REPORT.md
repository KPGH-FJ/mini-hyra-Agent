# 画像完备性探针：profile-only 作答 87.5% — 画像超过所有检索臂

- 探针：24 题分层抽样（每型 4：temporal/ku/pref/ss-assist/ss-user/ms），模型 = lme150_sc + ms-25 selfc 缓存
- 渲染器：`profile_probe.py` — 全量顶点按"实体×生活域"聚合成画像文档（一次 LLM 调用，要求逐事实保留具名主语+日期+数值；assistant 侧事实标注 "assistant suggested"）
- 作答：`ANSWER_SYS` 单调用，MEMORY=画像（无目录/无检索/无 gate/无 assist）
- 判官：Atria；产出 `profiles/*.profile.md`、`hyp_profile.jsonl`、`metrics_profile.json`

## 解读

1. **假设证实（探针规模）**：lifemodel 确实能一次性渲染出覆盖考题的用户画像——画像作答损失 ≈1/23 健康题（~4%），同时**消除整个检索层错误类**（R2 欠挑、gate 误杀）。
2. **画像=一等公民成立**：`export_profile()` 值得进 lifemodel API——它同时是压缩记忆（0.9×）和无检索作答通道。
3. **缩放未定**：本探针模型 6-65 顶点全量塞得进一篇文档；大模型（100+ recs）画像必须真压缩，届时损失率未知——这是探针结论外推的唯一风险。
4. **与检索栈的关系**：画像作答和"目录→digest"是两个互补通道——画像对聚合/枚举题有结构性优势（无欠取），但基数小；大记忆上的画像可能反过来需要检索兜底。
