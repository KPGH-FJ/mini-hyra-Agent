# P4 就绪清单 — 真实授权数据验证

合成基准（LifeStream v9）已经把系统压到满分前沿（195/195，60 种子
11,726 探针全绿，契约 29/29）。P4 的任务是验证这套系统在真实数据上
的泛化性——这一步需要用户单独授权后才能开始，本文档记录开工前
要备齐的东西和已知风险点。

## 需要用户提供/授权

1. **数据源授权**：聊天记录/日记/笔记/邮件等导出文件，或 API 授权。
   范围、期限、用途须明确（对应我们的 M5 scope/revoke 语义——
   授权本身就是第一个测试对象）。
2. **金标准**：真实数据没有合成 truth。可选标注协议：
   - 用户标注若干"事实点"（"我住哪/我做什么/我家情况"）作回归集；
   - 或自报一致性抽查：系统回答 vs 用户当场裁定对/错/过时。
3. **隐私边界**：明确什么能进资产、什么只过管不留存（raw 记录可
   设 expires_day——生命周期条款已就绪）。

## 系统侧已就绪的部分

- 摄入契约就是 `record` 结构（day/source/kind/slot/value/text）——
  真实数据只差一个**连接器层**把原始导出归一化成 record：
  - 时间戳 → day；发送人 → source/claimer；文本 → text；
    分类提示 → kind（statement/hearsay/suggestion…）。
- 实体与别名：真实数据天然多实体（家人/同事/朋友）——`about`
  顶点与 EA_ALIAS 机制直接复用；需要一个初始实体表（通讯录导出
  或对话中出现频率高的人名）。
- 用户控制全部可用：correct/forget(slot|range|about)/revoke_purpose/
  export/journal —— 真实场景的正确性已由契约测试 + 60 种子扫过。
- NL 查询面（query.py）：规则路由覆盖 28 探针类型；真实数据上
  可换 LLM 路由（同 `_probe_for` 输出契约）。

## 已知风险（先想清楚的）

- **文本 → slot/value 归一化**是最大开放问题：合成数据里 value 是
  干净的槽值，真实文本要抽（LLM 抽取 + 不确定度）。这可能成为
  M1 的一个新子轮。
- **密度**：真实记录可能日数百条 —— density×5 已验证扩展性，
  但探针计量口径要在真实体量下重校。
- **评估协议**：没有合成 truth 就要靠抽检+用户裁定；先小规模
  （1 人 × 30 天 × ~50 个金标准问题）再扩大。
- **成本**：真实摄入的 LLM 抽取成本要实测记账 —— 评测器的
  probe_bytes/asset_bytes/token 计量已通用，直接沿用。

## 开工 checklist

- [ ] 用户书面授权（范围/期限/用途）+ 金标准标注方案敲定
- [ ] 第一个连接器（选导出格式最简单的一种数据源）
- [ ] 实体表初始化（别名→规范名）
- [ ] 小样本跑通：灌入 → 抽检回答 → 用户裁定 → 首次迭代
- [ ] 评估协议文档：裁定口径、抽样密度、隐私处置
