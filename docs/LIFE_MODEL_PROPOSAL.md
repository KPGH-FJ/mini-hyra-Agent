# Life Model 研究提案（v0）

对应 `LIFE_MODEL_RESEARCH_BRIEF.md` §6 的"第一份交付"：对目标的理解、最关键的未知、
已有方法与不足、候选、区分性实验、所需数据与资源，以及继续/调整/放弃判据。

## 0. 对目标的理解（一句话）

围绕同一个自然人，把持续到来的授权资料**沉淀成一份可修正、可控制、跨用途复用的
"理解资产"**，并用实验证明它比"直接用原文"和"简单记忆"更划算——收益要抵得过
形成、维护、检索、纠正的总代价。

## 1. 最关键的三个未知（按简报"期望效果→必要能力"推导）

**U1 更新的真实性**：新记忆进入后，相关判断是否真的变了？纠正是否真的传播到
派生内容？撤回/删除是否真的从后续推断中消除？——已有原型已提示"部分纠正没有
真正生效"，这是最要紧的可证伪点。

**U2 理解的净收益**：派生资产相对"完整原文检索"和"简单事实账本"两个强基线，
在任务质量、token/存储/检索代价上的净差是否为正？简报明说复杂资产不必然更优。

**U3 跨用途复用**：同一份资产能否服务训练时没预设过的用途（held-out 任务族），
还是每种用途都要重新画像？这决定"一个 Life Model"是否成立。

## 2. 已有方法与不足（简报§5 + 公开文献共识）

| 路线 | 代表 | 不足 |
|---|---|---|
| 原文检索 (RAG) | 全量记录+向量召回 | 无概括，更新=重索引，无法表达"已撤销" |
| 事实账本 | 结构化 fact store | 难表达条件/例外/置信度，冲突靠人工 |
| 情节+反思 | Generative Agents 式 | 反思结论无 provenance，纠错难追踪 |
| 层级摘要 | 摘要树/递归压缩 | 细节损失不可逆，更新需重写上游 |
| 时间关系图 | temporal KG | 构建成本高，schema 僵化 |
| 参数记忆 | 微调个人 LoRA | 删除/审计困难，更新灾难性遗忘 |

## 3. 区分性实验（Evolve 的核心仪器）

一个方法只有在同一信息流上、同等可知信息、同等资源下击败三个基线才算赢。

**LifeStream 基准**（详见 `tasks/life_model/`）：

- 合成人生流：一个脚本化 persona 在 T 天产生的多源记录流——本人陈述、
  他人转述、助手生成内容、文档/设备记录；内含**真实变化**（决定翻转、
  偏好漂移）、**纠错**、**过期约束**、**冲突**和**故意噪声**。
- 生命周期协议：T 个检查点把流切成阶段；候选方法在每阶段
  ingest → build/update asset → 回答结构化探针 → 注入更新/纠错/撤回 → 再答。
- 探针分四类，每类对应一个未知：
  - *状态探针*（当前事实/约束是否正确——更新真实性）
  - *沿革探针*（过期与撤销信息是否被正确处理——防过时泄漏）
  - *迁移探针*（held-out 用途族——跨用途复用）
  - *成本记账*（资产字节数、每探针检索字节、LLM token、纠正操作数——总代价）
- 基线（同信息同资源）：`raw`（原文）、`ledger`（事实账本）、`rag`（记录检索）。
- score = 任务质量分 − λ·成本分；同时产出分项供分析。

## 4. 候选方法空间（hyra 要进化的东西）

每个解 = 一个 `solution/` 目录，`solve.sh` 对 LifeStream 跑完协议并写
`solution.json`。解的实现自由度是"记忆/理解资产"的设计：存储结构、
形成算法（抽取/概括/归纳）、更新逻辑（纠错传播、过期处理）、检索策略、
元数据（provenance/置信度/有效期）。种子解 = 最朴素的 append-only 账本。

## 5. 数据与资源

- **合成数据**：生成器确定性产出（seed 固定），避免真实个人数据的授权与
  隐私问题；简报§6 明确涉及个人数据需另行授权，v0 不用。
- **算力**：hyra harness（本仓库）+ Atria-Dawn-Preview 作为提案/探针模型；
  每解一次 sandbox 运行，基准为纯算法协议（探针用结构化检查，不耗 LLM）。
- **预算**：建议首个真实 run `--solutions 60 --workers 4 --wall-clock 7200`。

## 6. 继续 / 调整 / 放弃判据

- **继续**：任一候选在 score 上显著超过三个基线的最优者（>5%），且
  撤回探针正确率 ≥ 基线水平（说明更新真实生效）。
- **调整**：若候选普遍在"迁移探针"上退化——说明跨用途泛化是瓶颈，
  下轮收窄方向专门攻它；若全部败给 `raw` 基线——复杂资产净收益为负，
  回到 U2 重新设计资产形态。
- **放弃**：若连续两轮（≥120 commits）无任何候选超过 `ledger` 基线，
  或撤回探针正确率系统性低于 50%——说明"可控理解资产"在此协议下
  形不成优势，按简报§79 结论也是清楚有价值的研究结果。

## 7. 范围与授权声明

- 本阶段只用合成数据，不触达真实个人数据，不产生对外行动。
- Atria API 付费调用由现有 key 承担，用量经 harness 记账（report.json）。
- 若之后引入真实数据/对外行动，按简报§83 需单独明确范围与授权。
