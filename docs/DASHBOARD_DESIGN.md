# LifeModel 研究看板设计方案（v4）

> 目标：让一个研究者（包括未来的我们）打开看板，**60 秒内对齐三件事**——系统现在长什么样、研究走到哪了、眼下在攻什么、还差多远。再往下才是证据明细。

## 1. 读者与问题（先想清楚给谁看）

读者 = 研究者的我们自己 + 偶尔来审阅的协作者。看板必须按"问题顺序"组织，而不是按"数据有什么"组织：

| 读者脑子里的问题 | 看板要给的答案 |
|---|---|
| 研究现在什么状态？ | 一句话结论（哪个轮次、谁领跑、还差多少） |
| 系统长什么样？ | 五模块架构图 + 每个模块当前实现 |
| 之前每一步得到了什么？ | 研究脉络时间线（可读的历次结论） |
| 现在正在干什么？ | 当前轮卡片：目标、对手、进度 |
| 差距具体在哪？ | 题型热力图：哪些考点还没人做出来 |
| 证据在哪？ | 得分曲线、谱系、候选解明细、日志 |

## 2. 已有成果盘点（看板要展示的内容资产）

- **系统本体**：lifemodel 包，五模块（摄入/表征/更新/使用/控制），接口冻结、实现可换；当前在 v9.1 考题下 195/195 满分领跑
- **逐模块获胜机制**（已折叠进系统）：M2 时态流水账、M3 TMS 前提维护、M5 同意域视图+内嵌操作日志
- **进化实验史**：run_v5（M1，撞 100 提交上限，冠军 s0095=158.911）等 5+ 个 EB、34+ 计分解、死亡分析
- **方法论发现**：journal/时态边架构被纯净室独立复现（收敛吸引子）；逐模块折叠 > 整体进化
- **评测器资产**：LifeStream v9.1，~197 探针/29 题型；契约套件 31 条
- **基础设施经验**：Atria 流式修复、65536 cap、输入窗 60KB 预算

## 3. 行业做法借鉴

- **W&B / MLflow（实验追踪）**：可比较的 run 表 + 指标曲线 + 按参数筛选；我们已有（得分曲线、明细表），但缺"当前轮 vs 历史轮"的分组视图
- **观测性面板（Grafana/SRE）**：顶部一行 SLO/verdict，下面层层下钻；状态用颜色而非术语 —— 借鉴"一句话判定横幅"
- **Distill / Observable 式叙事**：结论先行、证据后随、渐进披露（progressive disclosure）—— 看板自上而下就是"结论→脉络→证据"
- **缺口地图**：类似覆盖热力图，把"还没人做对的题型"可视化 —— 这是我们研究最该有的独创板块，直接回答"差在哪"
- **可读性**：所有面向读者的文案用大白话；术语（EB、probe、eval_v）只出现在下钻明细层

## 4. 信息架构 v4（自上而下）

```
┌─ 状态横幅：run_v7 W2 进行中 · 领跑 lifemodel v1 195.0 · 差距 ~36 分在深史题 ─┐
├─ ① 系统是什么：五模块架构图（点击看当前实现）＋ 一句人话定位            ─┤
├─ ② 研究脉络：时间线，每轮一句话结论（已有）                            ─┤
├─ ③ 当前在做什么：当前轮卡片（目标模块/对手分/已计分解数/剩余时间）      ─┤
├─ ④ 差距地图：题型 × 选手热力图，红的=没人做出来 → 下一轮目标就在这      ─┤
├─ ⑤ 排行榜：选手表（人话说明列在最前）                                  ─┤
├─ ⑥ 证据区：得分走势 / 解的谱系 / 候选解明细 / 运行日志                  ─┘
```

关键新增：
- **状态横幅**（最顶一行）：`当前：{轮次} · 领跑：{name} {score} · 缺口：{题型}差{n}分` —— 数据从 research.json `current` 字段读，我每轮维护
- **差距地图**：题型行 × 选手列的色块矩阵，每格 = 该选手在该题型的得分率（已有 fb.breakdown 数据）。红格自动暴露"下一轮打哪"。这是把研究结论直接画出来
- **当前轮卡片**：本轮目标（人话）、对手分（lifemodel/基线/上届冠军）、进度条（commits/计分/死亡）

## 5. 数据方案（不动接口，只扩 research.json）

- `research.json.current`：当前轮对象（轮次名、目标、进行中 EB、截止、参考分）— PI（我）每轮维护
- `research.json.timeline`：已有（历次结论）
- `research.json.gap_map`：题型 × {lm, s0095, tms, esr} 得分矩阵 —— 从各最优解的 breakdown 提取，每轮收官我更新
- EB 数据照旧走 /api/status+/api/eb，不动

原则：**看板内容 = research.json 一处维护**。web.py 只渲染，不藏知识——以后每轮研究推进只改 JSON。

## 6. 落地清单

- [ ] web.py：状态横幅 + 当前轮卡片 + 差距地图渲染（纯 JS/SVG，零依赖不变）
- [ ] research.json：current/gap_map 字段；timeline 已有
- [ ] 文案大扫除：状态徽标、错误种类标签人话化（502→"网关抖动"等）
- [ ] 部署链路：实验室 pull + 重启 serve（现有流程）

## 7. 不做的事（同样重要的取舍）

- 不做交互式筛选/参数对比器（W&B 那种）——我们的实验单元是"轮"不是"run"，90% 的对比需求被排行榜+差距地图覆盖；复杂度不值
- 不做登录/权限 —— preview 网关已有认证
- 不做实时推送 —— 现有轮询刷新够用
